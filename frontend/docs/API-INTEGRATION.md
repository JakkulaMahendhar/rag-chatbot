# API Integration

The exact backend contract this frontend was built against, verified by
reading the actual FastAPI source (not assumed) - see the file reference
next to each endpoint. `types/*.ts` mirror these shapes field-for-field.

## Auth (`app/auth/router.py`, `app/auth/schemas.py`)

| Endpoint | Auth | Notes |
|---|---|---|
| `POST /auth/register` | none | Returns `UserResponse` (id/email/is_active), not a token. Frontend chains an immediate `/auth/login` call after (see `lib/auth/auth-context.tsx`). |
| `POST /auth/login` | none | Returns `{access_token, token_type}`. Rate-limited (5/60s per IP, `app/core/rate_limiter.py`) - a `429` includes a `Retry-After` header, surfaced in the login/register forms. |
| `GET /auth/me` | Bearer | Returns only `{id, email}` - not the full `UserResponse`. Used for session restoration on load and to validate a stored token. |

JWTs expire in 30 minutes with **no refresh token** (`app/auth/jwt.py`). No
forgot/reset-password endpoints exist - those pages were deliberately not
built.

## Documents (`app/api/upload.py`, `app/api/document.py`, `app/schemas/*.py`)

| Endpoint | Notes |
|---|---|
| `POST /upload` | `multipart/form-data`, field name `file`. Returns **202** immediately (`{document_id, filename, status, message}`) - only registers the file, does not process it. Processing happens in a separate worker (`app/worker.py`); poll `GET /documents/{id}` for status. |
| `GET /documents` | Lists the current user's documents only. |
| `GET /documents/{id}` | `403` (not `404`) for both "doesn't exist" and "belongs to another user" - the API doesn't distinguish, so neither does the frontend. |
| `DELETE /documents/{id}` | Same `403` behavior as above. |

`status` is one of `pending | processing | completed | failed`. `hooks/use-documents.ts` polls every 3s only while a document is pending/processing.

## Chat (`app/api/chat.py`, `app/services/rag_chat.py`)

`POST /chat` - **no streaming**. A single blocking JSON response:

```ts
{
  conversation_id: string;  // generated by the backend if you omit it
  question: string;
  answer: string;
  sources: SourceReference[];
  search_evaluation: {...};  // not surfaced in the UI
  evaluation: {...};         // not surfaced in the UI
}
```

`SourceReference` (`app/models/source.py`): `document_id`, `chunk_id`,
`filename`, `content`, `score` (nullable), `rerank_score` (nullable).

**Two things that are easy to get wrong here, both hit during build:**

1. `SourceReference.filename` is the **on-disk storage name**
   (`app/services/document_processor.py` tags chunks with
   `location.name`, the UUID-based `StorageService` path), not the
   original upload name. The frontend cross-references `document_id`
   against the already-fetched documents list to show the real filename
   (`hooks/use-document-filename.ts`) instead of the storage UUID.
2. There are no page numbers anywhere in the pipeline - PDF text is
   concatenated across all pages before chunking
   (`app/services/parser.py`), so page boundaries are lost. Don't
   fabricate a page number in source citations.

Conversation history is **in-memory only**
(`app/services/conversation_store/memory.py`) - no persistence, no
listing endpoint. The frontend keeps the active conversation in React
state and starts fresh on reload; there is no chat history feature.

## Search (`app/api/routes/search.py`, `app/models/search.py`, `app/schemas/search.py`)

`POST /search` - `{query: string (min 3 chars), top_k?: number (1-10, default 3)}` →
`{query, results: SearchResult[]}`.

`SearchResult.score` is a **raw Chroma L2 distance** (`app/services/search.py`
returns `results["distances"]` directly) - lower is better, unbounded, not a
0-1 similarity. Converted to a display relevance percentage using the same
`1 / (1 + distance)` formula `app/services/hybrid_search.py`'s own
`_normalize_distance` already uses, rather than inventing a different
convention.

## Not implemented (no backend support)

Collections/knowledge-bases, chat history list/rename/delete, dashboard
statistics, analytics, document reprocess/download, forgot/reset password.
None of these have a corresponding endpoint - see the main README/commit
history for the full reasoning on scoping these out of v1.
